# Jev Reflex Guided：制御と検証記録

確認日：2026-10-03。現在の配布版はv1.4.0-r3、modeは `jev-reflex-guided`、protocolは `jev-reflex-guided-v1` です。

## 修正した問題

要求間隔70msでも応答に400msかかる環境では、古い観測への回答が届きます。旧版の固定した遅延初期値、描画まで入力を待つ処理、鳥が隙間の中央をまたぐ状態の説明が早期死亡につながっていました。

r2は開始前に実通信を3回測定し、そのうち初回の接続準備を除いた値で遅延推定を始めます。通常の回答も通信経路全体の所要時間を測ります。最近20件の中央値・p90を使い、先読みは中央値に要求間隔を足した値までに制限します。単発の遅延急増で遠すぎる未来を予測しないためです。

早く届いたJevの回答はタイマーで適用時刻に実行します。描画フレームまで待ちません。遅れが要求間隔（最大250ms）を超えた回答は捨てます。FLAPでepochを更新し、前の軌道の回答を失効させます。最大12件を並列送信します。

## 完成版の仕様

要求間隔は50〜500ms、初期値100ms。保存済みの間隔は保持します。ゲームの速度、重力、隙間、ランダム生成は変えません。開始・再挑戦は元ゲームの標準操作で、その後のFLAP／WAITはJevが選びます。ローカルによる救済・回答の上書きはありません。目標設定、固定100点目標、得点による自動停止、ログ保存・コピー・出力はありません。

開始前の3回もAPI上限・料金に含まれ、回答をゲームへ適用しません。上限が小さい場合は開始後の要求を1回残す範囲で測定回数を減らします。r3ではAPI上限の1000回固定制限を削除しました。初期値0（無制限）、1以上で任意の回数を指定できます。保存済みの値は保持し、自動再挑戦でも回数をリセットしません。以下の性能測定はr2・上限1000回での結果です。r3の変更は上限設定とその適用だけです。

Canvasから鳥・隙間・障害物を観測し、固定の攻略条件と物理・通信時間をJevへ送ります。障害物が見えるときは画面の上下半分という紛らわしい説明を省き、鳥の全身が隙間の上下半分にあるか、中央をまたぐかを区別します。次の要求間隔まで進んだ位置と下端の余裕も数値として伝えます。クリックの推奨値をローカルで算出しません。

物理は元ゲームと同じ半陰的更新で外挿し、実測した描画間隔と50msの物理更新上限を反映します。通過済み障害物は除きます。画素の読み取りを要求時に絞り、間の描画では物理追跡を続けます。100ms・60fpsでは毎フレーム読み取りに比べ約6分の1の読み取り頻度です。

## r2と旧版の比較

以下は実Jev `jev-latest`、要求間隔100ms、seed 7・19・43を各1回、再挑戦なし、上限1000要求の比較です。旧版も100msへ設定して比較しました。応答が速い条件の中央値は約164〜171ms、遅い条件は実通信に230msを加え中央値約396〜401msでした。追加遅延中もゲームは止めません。

| 条件 | 旧版の3得点 | r2の3得点 | 平均：旧版 → r2 | 0点：旧版 → r2 |
|---|---|---|---|---|
| 通常応答 | 0・0・17 | 91*・99*・17 | 5.7 → 69.0* | 2/3 → 0/3 |
| 約400ms応答 | 0・0・0 | 12・12・34 | 0 → 19.3 | 3/3 → 0/3 |

*91・99はAPI上限1000回で終了した測定値です。平均69.0もこの上限付き測定の平均です。

0点の試行も平均へ含めています。上限に達した試行は自然な死亡による成績ではなく、測定終了時の下限です。乱数seedを揃えても通信とモデル回答には変動があり、各条件3回でユーザー環境の平均・成功率を保証できません。100点到達は確認できていません。

通常条件の合計要求は旧版273回、r2は2214回、APIが返した入力トークン合計は326,640 → 3,927,239でした。合計得点17 → 207なので、1点あたり要求は16.1 → 10.7回、入力トークンは19,214 → 18,972で約1.3%減です。長く遊べる分、1開始あたりの総費用は増えます。r2の約400ms条件は650要求・1,117,084入力トークン・合計58点でした。旧版は0点なので得点あたり費用を比較できません。実際の請求額は測定していません。

以前の150ms推奨は10点までの短い比較によるもので、長いプレイの平均を保証していませんでした。今回のr2では実際の長いプレイを評価し、100msを初期値としました。今回50〜500ms全域を再比較していないため、100msを全環境の最適値とは主張しません。

## 検証方法と範囲

元サイトのローカルコピーをPlaywright・Chromiumで実行し、配布するcore/content/backgroundを実Jevへ接続しました。背景の装飾アニメーションのみ読み込まず、ゲームの物理・速度・障害物生成式は元のままです。seedとゲーム内部状態の参照は外部の測定専用で、Jevと制御処理へ非公開状態を渡しません。製品は通常のMath.random()を使います。

Chrome APIの保存・メッセージにはテスト用実装を使い、backgroundを別のJavaScript環境で動かしました。キーはbackgroundだけで保持します。環境の管理ポリシーで拡張機能のインストールが禁止されているため、Chromeへの実インストールは未検証です。ユーザーPCでの測定も行っていません。

当時の27件の自動テストが通過しました。遅延測定、予定時刻の入力、停止・キャンセル、epoch、キー境界、並列上限、不正回答、低FPS外挿、観測語彙、間隔設定を確認しています。UI検証16項目も通過し、100ms初期値、49ms拒否、500ms保存・再読み込み、開始・停止、ゲーム終了、ログ・目標設定の不存在、390px幅を確認しました。API上限5000回・0（無制限）の保存と再読み込み、無制限表示も確認しました。外部テストで1000回を超える送信、指定回数での送信停止、手動停止を確認しています。ページ実行時エラーはありませんでした。

測定結果は外部の検証ハーネスで採取しました。配布物にはログ機能・外部ハーネス・過去のログ集計ツールを含めません。

## 2026-10-03 診断ログ追加

実行中の要求送信・応答時間・回答の採用・破棄理由・WAIT/FLAP実行を調べられる一時的な診断ログを、開発ワークツリーへ追加しました。ゲーム上の「診断ログ」から集計と直近200イベントを見て、選択した実行をJSON保存できます。1タブ内の直近8実行、1実行あたり最大15,000イベントをメモリに保持し、再読み込み・タブ終了で消去します。APIキーとゲーム状態の全体は記録しません。

追加後の自動テスト28件はすべて通過しました。テスト用Chrome API環境でイベント分類、画面集計、JSON保存を確認しています。実Chrome上でこの追加UIを描画・操作する確認は未実施です。また、この開発変更はv1.4.0配布ZIPへまだ含めていません。
