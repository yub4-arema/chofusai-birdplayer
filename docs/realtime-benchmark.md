# Jev Reflex Neutral 実時間ベンチマーク（v1.4.0）

v1.4.0はJev自身のリアルタイム操作判断を測ります。ローカル側はCanvasの観測、時刻補正、通信制御を担当し、FLAPすべきかは判断しません。ゲーム本来の重力・速度・障害物生成を変更しません。

## 制御条件

- 初回の開始・再挑戦は元ゲームの標準入力を使います。その後、開始直後から約50ms間隔でJevに要求します。
- 質問は `FLAP` / `WAIT` の2択です。前の応答を待たず最大12件を並列送信します。上限到達時は要求だけをスキップし、ゲームは実時間で進めます。
- 800ms予定、16択、200msスロット、ローカル自動クリック、衝突シミュレーション、危険時の救済入力は使いません。
- `FLAP` は指定時刻にクリックを1回送り、`velocityY` を `flapVelocity` にします。`WAIT` は入力せず、現在の運動を続けます。

## 時刻補正と送信状態

各要求は `request_id`、`sent_at`、`observation_time`、`target_time`、`predicted_latency`、`flap_epoch` を持ちます。`target_time = sent_at + predicted_latency` です。最近の応答時間から遅延を推定し、描画時点の `y` / `velocityY` とゲーム重力、障害物速度で、目標時刻のプレイヤー位置・速度・障害物位置を外挿します。この計算は物理的な位置更新だけを行います。

送る状態には少なくとも次を含みます。

- プレイヤーの `y`、`velocityY`、`radius`
- 次とその次の障害物の `x` / 水平距離、幅、`gapTop`、`gapBottom`
- 画面高、重力、`flapVelocity`、`speedX`
- `target_time`、`predicted_latency`
- 観測値の言語化（rising / falling / level、gapとの位置関係、upper / lower half）

衝突するか、安全か、FLAPすべきか、狙う高さは何かという判断は含めません。Jevへのcriteriaには、FLAPが速度を設定すること、WAITが入力なしで運動を続けることだけを定義します。

## 応答の適用とsupersession

- 目標時刻より早く届いた回答はキューに置き、目標時刻に実行します。
- 目標時刻より遅く届いた回答は、250ms以内なら到着時にすぐ適用します。それより古ければ `stale` として破棄します。
- FLAPを実行したら `flap_epoch` を増やします。前のepochで送信済みの未着回答と、適用待ち回答は `superseded` として無効化します。WAITではepochを変えません。
- ゲームオーバー後の回答は操作に使わず、`game_over` として記録します。通信エラーや古い回答でローカル操作を補いません。

## ログ

要求イベントにはID、送信・観測・目標時刻、予測遅延、epoch、Jevへ送った状態を含めます。回答と結果は別イベントにし、受信時刻、実レイテンシ、選択、信頼度、選択確率、実モデル、実行時刻・遅れ、または破棄理由を残します。通信失敗は `network_latency`、`api_error`、`jev_decision`、`harness` などの分類を記録します。

ゲームイベントには得点、生存時間、ゲームオーバー理由を残します。画像、APIキー、応答本文は記録しません。詳細イベントは直近2400件で、それより古いイベントを削除した場合は `truncated` を立てます。累積指標は試行終了まで保持します。

最低限の指標:

- 得点、生存時間、APIレイテンシのp50 / p95 / 最大値
- FLAP / WAIT判断数、実行数、信頼度
- 観測された最大in-flight数、superseded数、stale数、遅延適用数
- 要求スキップ数、APIエラー数と失敗分類
- 手動入力数、完了試行と打ち切り試行

## 採取と集計

本番ベンチマークでは `random_obstacles = true` のまま実行し、ゲーム速度・重力・隙間幅を変えません。モデルを比較するときは拡張機能の版、モデル、API接続先、画面サイズ、API要求上限、自動再挑戦を記録し、複数回を交互に実行します。API上限・手動停止・通信障害による打ち切りは自然なゲームオーバーと分けて扱います。

各開始の最終ログを保存し、オフラインで集計します。

```sh
node tools/summarize-logs.mjs log1.json log2.json > summary.json
```

出力は条件が一致するログをまとめ、完了ゲームのスコアと生存時間、APIレイテンシ、行動分布、confidence、in-flight、superseded / stale / 遅延判断、スキップ、失敗分類を集計します。異なる質問ハッシュや制御条件を同じ集計グループに混ぜません。

ゲームの障害物は元の `Math.random()` で生成されます。同じ設定でも障害物列、通信、描画時刻が異なるため、単一試行から性能を断定しません。ゲーム画面を表示したまま実行してください。
