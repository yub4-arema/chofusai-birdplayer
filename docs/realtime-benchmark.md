# Jev Reflex Guided：制御と検証記録

確認日：2026-10-03。現在の版はv1.4.0（更新）、modeは `jev-reflex-guided`、protocolは `jev-reflex-guided-v1` です。

## 完成版の仕様

要求間隔は50〜500ms、初期値150ms。得点の設定機能、得点による自動停止、診断ログの採取・コピー・出力を削除しています。Jevへの質問は生存して得点を伸ばすことを目的とし、100点を固定の目安として伝えます。この数値はローカルの停止条件や設定項目ではありません。

ゲームの重力、速度、隙間、ランダム生成は変更しません。開始・再挑戦は元ゲームの標準ボタンです。その後のFLAP／WAITはJevが選び、ローカルによる救済操作や回答の上書きはありません。

## 観測・外挿・応答

- Canvasから鳥、次とその次の障害物、隙間、色、点数を観測します。得点はゲームの表示から読みます。
- 最近20応答の所要時間から遅延を推定し、`target_time = sent_at + predicted_latency` とします。
- ゲームと同じ半陰的な物理更新で、鳥と障害物の位置を目標時刻へ外挿します。目標時刻で通過済みの障害物は除き、見えている次の障害物を繰り上げます。見えていない障害物は生成しません。
- 隙間の上下半分と画面の上下半分を別に表現し、短い英語の観測文を付けます。攻略条件は隙間より下、または下半分で上昇中でなければFLAP、上・上半分・隙間内で上昇中ならWAITという固定の説明です。床と天井も説明します。
- 最大12件まで並列送信します。早い回答は目標時刻まで待ち、250ms以内の遅れなら到着時に適用します。それより古い回答は破棄します。
- FLAP後はepochを増やし、前epochの保留回答を失効させます。FLAP直後の観測を次の描画まで更新せず再利用することはありません。
- 停止時は要求をキャンセルし、古い開始からの回答を新しい開始へ適用しません。

完成版が保持するのは現在の表示用カウンタ、進行中の要求・回答キュー、遅延推定用の数値、ベスト得点です。要求状態や判断履歴を保存・コピーする機能はありません。

## 呼び出し頻度の比較

8つの間隔 × 3seed = 24開始を実Jevで比較しました。モデル指定は `jev-latest`。各開始は最大3ゲーム、API上限500、10点以上で比較を終了します。10点は実験の共通測定基準で、完成版の設定や停止条件にはなりません。

再現性のため、検証用ページの乱数だけをseed 7・19・43で初期化しました。ゲームの物理と障害物生成式は変更していません。最終製品は通常の `Math.random()` のままです。通信・描画は実時間で進み、応答待ちでゲームを止めません。

| 要求間隔 | 3開始中の10点到達 | 成功した開始の平均要求数（再挑戦込み） |
|---|---:|---:|
| 50ms | 3/3 | 273.7 |
| 100ms | 3/3 | 115.0 |
| 125ms | 3/3 | 117.7 |
| **150ms** | **3/3** | **98.0** |
| 175ms | 2/3 | 104.0 |
| 200ms | 1/3 | 94.0 |
| 250ms | 0/3 | — |
| 300ms | 0/3 | — |

50msの要求数は192・347・282、150msは73・112・109。平均要求数の減少は `1 - 294 / 821 = 64.2%` です。これはAPI要求数の比較で、請求額の減少率を直接測った値ではありません。失敗して早く終わった開始を「安く到達した」とは扱っていません。

今回の範囲では150msをコスト重視の推奨値にしました。100msでは3seedとも初回に到達し、150msでは1seedで再挑戦が必要でした。175ms以降は失敗が増えます。各seed・間隔を1回ずつの短い比較であり、任意の通信環境や長いプレイでの最適性・成功率は保証できません。

この比較には計測機能がある実験版を使いました。完成版では計測機能と得点による停止を削除し、別途通常のランダム障害物で動作を確認しています。比較後に、外挿時に通過済みの障害物を除く処理も追加しました。

## 長いプレイの確認

ログを削除した版の150ms試行では、通常のランダム障害物で5ゲームが2・11・14・0・15点でした。479要求、手動入力0、ページ実行時エラー0。通過済みの障害物を外挿で除く修正後の150ms試行は6ゲームで0・0・1・21・10・8点、408要求、手動入力0、ページ実行時エラー0でした。

診断通知と旧通信経路も削除した最終コードの100ms試行では、通常のランダム障害物で54・22・1点でした。1000要求の上限で停止し、手動入力0、ページ実行時エラー0。応答時間は中央値166ms、p95 214ms、最大463msでした。54点のゲームは約64秒続きました。この追加試行は乱数seed比較とは別です。

100点には到達していません。10点までの比較結果を、100点まで安定して続くことの証拠とは扱いません。

以前の直接接続ハーネスでは、50ms・1000要求の終了時に42点で生存していました。この42点は拡張機能本体の成績とは別です。参考記録として残します。

## 検証方法と範囲

元サイトのローカルコピーをPlaywright・Chromiumで実行し、実際の `core.js`・`content.js`・`background.js` を接続しました。API通信は実Jevです。背景の装飾アニメーションだけを読み込まず、ゲームの物理・速度・障害物は元のままです。

Chrome APIの保存・メッセージ境界にはテスト用実装を使い、backgroundを別のJavaScript実行環境で動かしています。キーはbackgroundだけで保持します。**Chromeへ拡張機能を丸ごとインストールした試験はしていません。** ページ上の実コードとAPI通信を確認する試験です。

15件の自動テストで、キーの境界、接続先分離、時刻とepoch、並列上限、キャンセル、不正回答・通信エラー、要求間隔の範囲・保存・送信、観測と障害物の繰り上げを確認しています。別のUI確認では150ms初期値、49ms拒否、500ms保存と再読み込み、500msでの要求、停止後の要求停止、ゲーム終了時の停止、ログ・目標設定がないこと、390px幅の表示を確認しています。

旧版のログ集計ツールは過去の保存済み資料向けです。完成版の配布物には含めません。
